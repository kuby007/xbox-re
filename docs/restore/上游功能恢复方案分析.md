# 上游 webhtv@main 功能恢复方案分析

> 本轮只做**分析**，未改任何 app 代码、未混入发版线。方案已落在 `restore-upstream` 分支。
> 数据来自直接读取两个仓库 `main` 分支的全量文件树与关键文件（解析服务失败不影响，走的是仓库接口）。
> 下文「文件数」统一按 **blob（实际文件）** 统计，不含目录条目。

## 结论先说

**6 项功能都能补齐，但不是「把上游文件拷回来」这么简单。**

xbox-re 的精简不只删了文件，还在**同名文件里砍了大量方法**：

| 项目 | 上游 webhtv@main | xbox-re@main |
|---|---|---|
| 实际文件（blob） | 4781 | 2518 |
| tree 条目（含目录） | 5395 | 2914 |
| 上游独有文件 | **2293 个** | — |
| 同名但内容不同 | **424 个** | — |
| `Setting.java` | 64 KB | 28 KB（少 **161 个方法**） |
| `PlayerSetting.java` | 36 KB | 15 KB（少 **75 个方法**） |
| `PlayerManager.java` | 464 KB | 135 KB（少 **231 个方法**） |
| Room 数据库 schema | 35–45 | 35–37 |

所以恢复任何一项，都要同时补 **布局行 + 字符串 + 设置类方法 + 上游独有类 + 依赖**，缺一个就编译不过或点了没反应。

## ① 增强功能：短剧源 / 全局 webhome 皮肤 / git 云盘 / 远程托管 / 实验室

上游增强页比 xbox-re 多出的控件（两变体一致）：

- `shortDramaSource`（短剧源配置）
- `webHomeTheme`（全局 webhome 皮肤）
- `gitCloud`（git 云盘）
- `lab`（实验室）
- 另有 `siteName`、`audioSource`，mobile 还多 `comicSource` / `novelSource` / `localReader`

### 逐项判断

**远程托管要先纠正一个认识**：xbox-re **入口和弹窗都还在**（`remoteTrust` 已接线 → `RemoteTrustDialog.show()`，之前还修过它的弹窗跳位）。真正被删的是 `server/process` 里的 **25 个服务端类**（多线程代理 `MultiThreadProxy*`、Range 请求 `RangePlanner` / `SegmentedRangeEngine`、`ProxyRuntimeConfig*` 等，上游 45 个类 / xbox-re 只剩 20 个）。另外 `shellProxyConfig` 在两版都被 `setVisibility(GONE)` 主动隐藏。所以这项是「**补服务端能力 + 放开隐藏项**」，不是重做入口。

| 子项 | 上游独有 | 补齐所需 | 风险 |
|---|---|---|---|
| 短剧源 | 4 Java + 1 布局 + 1 drawable | `ShortDramaConfig`、`ShortDramaSourceDialog`、`ShortDramaQueueCoordinator` + `Setting.getShortDramaConfig()` | 低 |
| webhome 皮肤 | 65 Java + 4 XML + 8 个 `assets/webhome/*` | `WebHomeThemeDialog`、`WebTheme*` 全套 + 5 个 Activity 注册 | 中（65 个类互相引用，且与现有 WebHome 逻辑耦合） |
| git 云盘 | 34 Java（0.2 MB） | 全部 gitcloud 包 + **jgit**（`JGitDriveEngine` 实际引用） | 中（token 加密、账号存储） |
| 远程托管 | 25 个 `server/process` 类 | 补服务端类、放开 `shellProxyConfig` | 中（涉及本机 HTTP 服务与代理链路，和本轮新增的 `SiteFeature` 代理规则可能重叠，要划清边界） |
| 实验室 | 26 Java + 13 assets（**6.9 MB**） | lab 包 + `LabActivity` 等 5 个 Manifest 注册 + `commons-compress`（`LabEnv` 解 7z/tar/xz）+ `zxing-android-embedded`（`LabActions`）；**不需要** `work-runtime` | 中低 |

**关于「实验室对 app 空间影响」**（你点名要评估的）：
- 单 ABI 源数据：arm64 **4.2 MB**、v7a **2.7 MB**（`7zz`、`libc++_shared.so`、`proot` 等）
- 这些二进制压缩率低，进 APK 后预计 arm64 包 **+4~5 MB**，相对当前 43.7 MB ≈ **+10%**
- 另外 3 个依赖库约 +1~2 MB
- **判断**：算不上「不大」，但可接受。若你只想保留实验室 UI 不带 proot 运行环境，可以只恢复 Java 类、跳过 assets，功能会退化成「只能看不能跑」

## ② TMDB 全功能

- 上游独有 **216 个文件**（147 Java + 51 XML，2.8 MB），含详情页、演员页、剧集聚合、匹配缓存、凭据仓库
- 设置主页上游多 `tmdb` 入口；两变体 Manifest 多注册 `TmdbDetailActivity` / `TmdbPersonActivity` / `SettingTmdbActivity`
- **最大障碍：数据库**。上游 Room schema 到 **45**，xbox-re 只到 **37**，TMDB 的匹配缓存 / 观看进度都落在 38–45 的迁移里
- `Setting.java` 里 TMDB 相关 getter/setter（约 20 个）全被删

**结论**：可补，但属于「**大移植**」。要连 DB migration 一起搬，且上游 main 的 TMDB 是持续迭代版，和 xbox-re 的旧代码不一定同源。**建议单独一批、最后做**，先确认你只需要「TMDB 海报/详情」还是连剧集聚合、演员页、缓存全要。

## ③ 个性设置全功能

- 上游独有 33 文件（0.4 MB）：`SettingPersonalActivity` / `SettingPersonalFragment` + 两个布局、`PersonalRecommendationService`、`FlagPreferenceCache`、`/ui/custom/*` 一批自定义控件（`LutQuickPanel`、`KaraokeResultView`、`PlayerGesture` 等）

**结论**：中等工作量。注意 `/ui/custom/*` 里不少控件是给 **mpv / LUT / 卡拉OK** 用的，和 ⑤⑥ 耦合；若 ⑥ 不恢复，这部分只能补「能显示的壳」。

## ④ 去广告全功能

- 上游独有 **136 文件**（104 Java + 22 XML，1.1 MB）：`ad/audio/*` 音频指纹识别、规则仓库、跳过协调器、统计弹窗、`speech_ad_rules_v1.txt`
- 设置主页多 `ad`、`ai` 入口；leanback 多注册 `SettingAdActivity` / `SettingAiActivity`
- **体积隐患**：上游带 `tensorflow-lite` + `sherpa-onnx-jni.so`（arm64 **22.5 MB** / v7a **15.4 MB**）+ `libijkffmpeg.so`（8.9 / 6.6 MB）。若「全功能」包含 AI 音频识别，单 ABI APK **额外 +20 MB 以上**

**结论**：可补，但要先定口径——只恢复「HLS 广告片段过滤 + 规则 + 统计」（约 1 MB 代码，无大 so），还是连 AI 音频指纹（大幅增包）一起。

## ⑤ 播放设置 exo 配套设置（播放性能等）

- 设置页上游多 18–20 个 id：`mpvConfig` / `mpvRender` / `lut` / `blurayMenu` / `exo4kCompat` / `failureFallback` / `liveSourceFallback` / `musicNotification` / `audioBookNotification` / `rememberBrightness`
- 好消息：`PlaybackPerformanceSetting.java` xbox-re **保留了大部分**，只少 8 个方法；`PlaybackPerformanceCatalog` / `KernelPerformanceSetting` 也都在，只是被裁
- 上游独有 93 文件里，**真正属于「设置 UI」的只有十几个**（`PlaybackPerformanceDialog` / `Modal`、`ExoFrameSchedulingExperimentSetting`、`IjkPerformanceSetting`、`MpvPerformanceSetting`、`PlaybackPerformanceUiPolicy`），其余是 exo 渲染器 / FFmpeg 解码器 / native 静态库（`third_party/exo-dv5-native/prebuilt/*.a`，单是 `libshaderc.a` 就 41 MB，编译用不进 APK）

**结论**：**这一项最划算**——只补设置项 + 策略类，不动 mpv/ijk 内核，就能把「播放性能」那排开关找回来。建议**优先做**。

## ⑥ 播放器 / 内核 / 系统选项

- 上游独有 **522 文件**（386 Java），`PlayerManager` 少 231 个方法，`PlayerSetting` 少 75 个
- 单 ABI 需要的二进制：

| 类别 | arm64 | v7a |
|---|---|---|
| `assets/mpv-libs/*.so` | 44.5 MB | 38.5 MB |
| `jniLibs/*.so`（ijkffmpeg / sherpa-onnx） | 33.6 MB | 23.5 MB |
| 合计源数据 | **78.1 MB** | **62.0 MB** |

- 还带 `app/libs/*.aar`（forcetech / jianpian 5.4 MB）、`nextlib-media3ext`、`nodejs` 子项目、5 个 lab Activity + `NodeService` / `LabRuntimeService` 注册

**结论**：**能补，但代价最大**。当前 43.7 MB 的包会接近翻倍（预计 100 MB+），和你「app 空间」的考量直接冲突。而且这不是「加几个开关」，是换整套播放内核。

**请先定口径**：如果你说的「系统选项」只是**设置页里那些开关**（内核列表、渲染方式、解码选择），我可以只补 UI + `PlayerSetting` 方法，不搬 so，成本小；但这些开关在没有对应内核时不会真正生效。要真生效就得接受体积。
