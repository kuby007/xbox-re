## 1. 接口兼容现状

官方契约（真实规则命中）**134 个 API / 15065 次调用**，**134/134 符号可见**，四档如下（阶段八更新了 `bridge` 档的实际状态）：

| 档位 | 数量 | 实际状态 |
|---|---|---|
| `full` | 93 | 纯 JS 真实现，可用 |
| `bridge` | **25** | **已补齐语义**：21 个 Java 真实现 + 1 个 JS 层 CryptoJS 兼容对象等效承担（MD5/AES 仍走 Java 桥）+ 3 个明确降级 |
| `delegate` | 12 | 转交 JsT4 / shim / 宿主，有条件可用 |
| `degrade` | **4** | 明确不可用，显式标记不伪装成功 |

### 1.1 25 个 bridge 档：从「有符号、无语义」到「有语义」

`HikerBridge` 的 `@JavascriptInterface` 方法 **13 → 31**；新增纯 JDK 的 `HikerApi`（`call(name,argsJson)` 分发 35 个方法名）、`HikerJson`、`HikerQR`。

| 类别 | API | 阶段八结果 |
|---|---|---|
| 摘要/对称加密 | `md5`、`aesEncode`、`aesDecode` | ✅ JDK `MessageDigest`/`Cipher`，encode/decode 往返实测通过 |
| 非对称加密 | `rsaEncrypt`、`rsaDecrypt` | ✅ X509/PKCS8，1024 位密钥往返实测通过 |
| CryptoJS | `getCryptoJS` | ✅ JS 层返回兼容对象，`MD5/AES.encrypt/AES.decrypt` 走 Java 桥；不再返回降级标记 |
| Cookie / 缓存 | `getCookie`、`fetchCookie`、`fetchCache` | ✅ 按域 jar + TTL 缓存；实测第二次命中缓存、服务端仅 1 次请求 |
| 批量 / POST | `batchFetch`、`batchExecute`、`postRequest` | ✅ 4 线程并发，JS 层把 JSON 数组字符串还原成数组 |
| 下载 / 文件 | `downloadFile`、`requireDownload` | ✅ 二进制落盘 + `readFile` 读回 |
| M3U8 | `cacheM3u8`、`batchCacheM3u8`、`clearM3u8Ad`、`clearM3u8AdLazy` | ✅ 内容抓取 + 相对分片绝对化 + 落盘 + 启发式去广告 |
| 懒规则 | `parseLazyRule` | ✅ 同步取页 |
| 系统 / 工具 | `getIP`、`convertBase64Image`、`createQRCode` | ✅ IPv4、base64 图片落盘、QR → SVG data URI（矩阵与 Python `qrcode` 逐格一致 6/6） |
| 内核依赖 | `fetchCodeByWebView`、`x5Rule`、`parseLazyRuleAsync` | ⚠️ **仍降级**：返回空串并写 `degraded` 留痕，不伪装成功 |

额外实现 10 个 EXTRA 能力：`requireCache`、`fixM3u8`、`refreshVideoUrl`（302 跟随）、`getCpuAbi`、`findReachableIP`、`ipping`、`getCryptoJS2`、`writeHexFile`、`readFile` 为真实现；`refreshX5WebView` 降级。

### 1.2 明确降级的 4 个（`degrade` 档）

`startProxyServer`（本地代理服务）、`registerDNS`、`registerTask`、`unRegisterTask`。仍只上报留痕、不执行。

### 1.3 能力级缺口（不在 134 API 清单内，属于形态/引擎层）

| 能力 | 状态 | 原因 |
|---|---|---|
| X5 内核嗅探 / X5 Parser | 不可用 | 宿主 WebView 非 X5 内核；`fetchCodeByWebView`/`x5Rule` 因此降级 |
| 私有加密规则 `evalPrivateJS` / `loadJavaClass` | 只识别、不执行 | 需加载 Java 字节码 |
| Rhino 专有语法规则（`JavaAdapter`/`Packages.`/`importPackage`） | 只识别、不执行 | WebView JS 引擎非 Rhino |
| Python（Chaquopy）规则 | 只识别、不执行 | 未引入引擎 |
| 原生 UI：57 `col_type` / 34 Holder / 167 图片映射 | **刻意不做** | 走独立 WebView 路线，不追求像素级复刻 |
| `fy_bridge_app` 28 方法的语义 | ✅ 已接 Java 桥 | `getCookie`/`parseLazyRule`/`clearM3u8Ad` 等已转发到 `HikerBridge.call` |
| M3U8 本地代理服务 | 未做 | 当前是内容级改写 + 落盘，不是本地代理 |
| 完整 AES/CryptoJS 等价 | 部分 | key 非 16/24/32 时按 MD5 派生，覆盖常见写法，不等价于 OpenSSL EVP 派生 |
| QR 范围 | 受限 | version 1~10 / ECC-M / byte 模式 / 固定 mask 0，超容量明确留空 |

### 1.4 更贴近体感的数字

全库 78 条真实规则，**离线 stub 口径 32/78**（阶段六 31，未回退）。134/134 是"调用不抛 undefined"，32/78 是"整条规则能出 `setResult`"，两者不是一回事，且 32/78 未经过真机回归。

## 3. 两条出包路径

### 路径 A：现在就出「预览包」（可装、可演示链路）

能跑通：首页独立入口 → 口令 CRUD → 取口令数据 → 生成站点 → 站点运行 → 桥接播放器，93 个 `full` 档纯 JS 规则，**以及加密、Cookie、批量请求、下载、M3U8、二维码等原本会落空串的规则**。

```bash
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-21
# 把本地 hiker-entry/ 的改动合并进分支后
./gradlew :app:assembleLeanbackDebug
```

`app/build.gradle` 无需改动；无 release 签名时自动用 debug 签名。

### 路径 B：出「可用版」

上一轮卡住的两项 P0，**① 25 个桥方法无语义已闭合，② 真机探针仍在**：

1. 做最小真机探针，确认 `addJavascriptInterface` 同步 `req` 在真机 WebView 上能回调；
2. 真机重跑全库，把 32/78 提升后再发布；
3. 手机 flavor 补入口、`hiker://files` 接真实存储、`normalizePlayData()` 接入播放器 `flags`（P1）。

> 风险提示：3 个内核依赖 API（`fetchCodeByWebView`/`x5Rule`/`parseLazyRuleAsync`）与 4 个 `degrade` 能力仍不可用——**不会静默假成功（有 `degraded`/`lastError` 留痕），但功能确实缺失**。X5 嗅探类规则仍不能当"完全支持"宣传。
