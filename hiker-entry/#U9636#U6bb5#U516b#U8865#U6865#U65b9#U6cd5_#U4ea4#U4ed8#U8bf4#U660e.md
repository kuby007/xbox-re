# 阶段八 · 补桥方法交付说明

> 触发：上一轮结论里 `bridge` 档 25 个官方 API「有符号、无语义」，Java 侧 `HikerBridge` 只有 13 个方法，多数业务调用返回空串。
> 本轮把这条 P0 补齐，并额外补了 10 个 EXTRA 能力。

## 结论先行

**25 个官方 `bridge` 档 API 中，21 个在 Java 侧有了真语义、1 个由 JS 层 CryptoJS 兼容对象等效承担（MD5/AES 仍走 Java 桥）、3 个明确降级；另有 10 个 EXTRA 能力一并实现（9 真实现 + 1 降级）。合计 `HikerApi` 分发 35 个方法名。**

`HikerBridge` 的 `@JavascriptInterface` 方法从 **13 → 31**；`HikerApi` 零 Android 依赖，可 `javac` 单独编译与断言，不必等真机。

## 1. 补了什么

### 1.1 分层（新增 3 个 Java 类 + 1 个通用入口）

| 层 | 文件 | 职责 |
|---|---|---|
| 参数还原 | `HikerJson.java`（新） | 极简 JSON 解析/序列化 + 自建 Base64（兼容 API 24，不用 `java.util.Base64`） |
| 二维码 | `HikerQR.java`（新） | 完整 QR 编码链：位流 → RS 纠错 → 交织 → 功能图形 → 格式/版本信息 → 掩码 → SVG |
| 业务实现 | `HikerApi.java`（新） | `call(name, argsJson)` 分发 35 个方法的真语义 |
| Java 桥 | `HikerBridge.java`（改） | 新增 `call` / `apiCapabilities` / `apiReport` + 18 个按官方自然签名的具名方法；原 13 个不动 |
| JS 转发 | `hiker_api_surface.js`、`hiker_bridge_adapter.js`（改） | `bridgeCall` 优先 `HikerBridge.call`、参数显式序列化、数组还原、CryptoJS 兼容对象、降级留痕、网页桥转发 |

**为什么加通用 `call(name, argsJson)` 而不是逐个暴露 `@JavascriptInterface`**：`addJavascriptInterface` 遇到 JS 数组/对象会隐式 String 化（常见 `"[object Object]"`），且方法参数个数必须与 JS 调用严格一致，不一致就抛错。统一入口后 JS 侧用 `JSON.stringify(args)`、Java 侧用 `HikerJson` 还原，25 个 API 的参数才不丢不串。具名方法作为「直接按方法名调用」的兼容兜底保留。

### 1.2 官方 25 个 bridge 档逐项结果

| 类别 | API | 结果 |
|---|---|---|
| 摘要/对称加密 | `md5`、`aesEncode`、`aesDecode` | ✅ JDK `MessageDigest` / `Cipher`，AES 支持 CBC（默认）与 ECB、可选 iv |
| 非对称加密 | `rsaEncrypt`、`rsaDecrypt` | ✅ X509 / PKCS8 密钥，兼容 PEM 与纯 Base64 |
| CryptoJS | `getCryptoJS` | ✅ JS 层返回 CryptoJS 兼容对象，`MD5/AES.encrypt/AES.decrypt` 走 Java 桥；不再返回降级标记 |
| Cookie | `getCookie`、`fetchCookie` | ✅ 按域 jar，`Set-Cookie` 收集与复用 |
| 缓存 | `fetchCache` | ✅ 带 TTL 的内存缓存（实测第二次命中，服务端仅 1 次请求） |
| 批量/POST | `batchFetch`、`batchExecute`、`postRequest` | ✅ 4 线程池并发，返回 JSON 数组并在 JS 层还原成数组 |
| 下载/文件 | `downloadFile`、`requireDownload` | ✅ 二进制下载落 App 私有目录，`HikerHost.readFile` 可读回 |
| M3U8 | `cacheM3u8`、`batchCacheM3u8`、`clearM3u8Ad`、`clearM3u8AdLazy` | ✅ 内容抓取 + 相对分片绝对化 + 落盘 + 启发式去广告 |

EXTRA 10 个：`requireCache`、`fixM3u8`、`refreshVideoUrl`（302 跟随）、`getCpuAbi`、`findReachableIP`、`ipping`、`getCryptoJS2`、`writeHexFile`、`readFile` 为真实现；`refreshX5WebView` 明确降级。

## 3. 诚实边界（必须说清）

- **3 个内核依赖 API 仍降级**：`fetchCodeByWebView`（需 WebView 渲染后取 HTML）、`x5Rule`（需 X5 内核）、`parseLazyRuleAsync`（异步语义与同步桥冲突）。返回空串 + `degraded` 留痕，不是"已支持"。
- **M3U8 是内容级实现，不是本地代理服务**：只做抓取、相对地址绝对化、落盘与启发式去广告；`startProxyServer` / `registerDNS` / `registerTask` / `unRegisterTask` 四个 `degrade` 档仍不可用。
- **`clearM3u8Ad` 是启发式**：按广告关键词与 `DISCONTINUITY` 标记过滤，未逐条复刻海阔去广告规则。
- **加密的兼容口径**：AES 的 key 非 16/24/32 字节时按 MD5 派生，覆盖规则里最常见的 `(明文, key)` 写法；不等价于 CryptoJS 对 WordArray/passphrase 的 OpenSSL EVP 派生。RSA 只认标准 X509/PKCS8 编码。
- **QR 范围**：version 1~10 / ECC-M / byte 模式 / 固定 mask 0，未做 8 种掩码惩罚优选（不影响可扫性）；超容量明确返回空串。
- **缓存为进程内存级**，非磁盘持久化；Cookie jar 同理。
- **Rhino / Python / 私有加密规则 / Java 字节码 / 原生 UI** 仍只识别降级，未执行（与阶段七一致）。
- **完整 APK 仍未产出**：沙箱无 Android SDK / JDK 21 / Gradle 9.5.1 / NDK 29；`ecj + android-all.jar` 只验证独立模块可编译。
- **真机最小探针未做**：`addJavascriptInterface` + 一次同步 `req` 在真机 WebView 上的行为仍需过一遍；32/78 是离线 stub 口径。
- **mobile flavor** 首页仍需自行补一行 `HikerEntry.start(this)`。
