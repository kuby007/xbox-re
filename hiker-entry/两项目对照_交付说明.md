## 用户的问题

> 分析 `xingchen`、`hikerView` 是否**完全支持**我提供的那些接口；在两个项目上获取经验和教训，完善我们的项目，确保海阔生态下正常运行且**超越**这两个项目。

## 结论

**两个项目都没有"完全支持"，而且缺的不是同一类东西。**

| 项目 | 判定 |
|---|---|
| `hikerView`（海阔视界原版核心模块） | 规则引擎侧 **100%**（它就是接口定义方：`JSEngine.java` 3300 行、100 个 `@JSAnnotation` API、Rhino `rhino-1.7.13.jar`）；但 `fy_bridge_app` 只有 `help_web_bridge.json` 27 方法的**文档**，Java 实现不在开源范围（README 明说只开放核心模块），2024-04 停更，无宿主集成/口令/多桥适配 |
| `xingchen`（星辰播放器，webhtv 二开） | 用 `HkJsRuntime.java` 9211 行 + 60 个 `api/hk/` + 70 个 `ui/hk/` 类**逐行照抄 8.83**，语义等价覆盖高；但交付清单里明确堆着多条「本地已修、未编、待真机验」漏项，且不含 WebView 的 4 套同步桥形态、不做能力分级、不接宿主 fm SDK |

**根因**：用户历次给的「接口」横跨**三套体系**——① Rhino 规则引擎 API、② WebView 网页桥 `fy_bridge_app`、③ 宿主桥形态（v390 `FM_SHELL`/`FM_JSREQ`、wogg 异步 `window.fm`、oktv-cat `fongmiBridge`）。两个项目各占一侧，`hikerView` 开源部分连 ② 的实现都删了。

## 我们做了什么（超越点）

用 **`hikerView` 官方契约当尺子**（`help_js.json` 82 章 / `JSEngine` 100 API / `help_web_bridge.json` 27 方法 / `hiker_54.db` 真实命中 **134 个 API、15065 次调用**），把**`xingchen` 的真机教训**逐条落地：

| 补齐 | 文件 | 来源 |
|---|---|---|
| 官方 134 API 四档补齐（`full` 93 / `bridge` 25 / `delegate` 12 / `degrade` 4） | `hiker_api_surface.js`（新） | 阶段六只覆盖 36 个 |
| `hiker://` 10 类分发 + `file://` + 404/500 语义 + `clearTag` 不砍真实地址 | `hiker_scheme.js`（新） | xingchen 1.2.8「所有规则打不开」事故 |
| 新鲜作用域全量预置函数 | `installFresh()` | xingchen `getUaObject/getJsPlugin 未定义` 事故 |
| `fy_bridge_app` 8 → **28** 方法 | `hiker_bridge_adapter.js` | `help_web_bridge.json` 官方 27 + `fetch` |
| 播放交接 headers 对象数组 / `K@V` 双认、多线路 `names` | `normalizePlayData()` | xingchen 1.2.9 请求头全丢事故 |
| 兼容层 v1 → **v2**：`contract()` / `coverage()` / `scheme()` / `runInFresh()` | `hiker_compat.js` | — |

**结构性优势（两者都没有）**：显式 `@JavascriptInterface` 不经反射 → 天然免疫 R8 混淆改名；桥形态探测 + Promise 明确拒绝（反假阳性）；能力分级与显式降级；首页独立入口不混用；宿主 fm SDK / 口令 / 站点注入一条龙。

## 必须说清的边界

- **134/134 是"符号可见率"，不是语义完全支持**：阶段七的 25 个桥转发 API 已在阶段八补齐语义（21 个 Java 真实现 + 1 个 JS 层 CryptoJS 兼容对象 + 3 个内核依赖降级；`HikerApi` 35 方法 / `HikerBridge` 31 桥方法 / `verify_bridge_api.py` 51/51）；4 个降级能力（X5 嗅探 / 私有加密规则 / Java 字节码 / 代理服务）仍标记不可用。
- **Rhino / Python / 加密规则仍不执行**：`classify()` 只识别降级。
- **原生 UI 不移植**：57 `col_type` / 34 Holder / 167 图片映射刻意不做，走独立 WebView 路线。
- **完整 APK 未产出**：沙箱 Gradle 9.3.0 / JDK 20 / 无 Android SDK，仓库需 9.5.1 + JDK 21 + compileSdk 37 + NDK 29。
- **真机最小探针未做**；32/78 是离线 stub 口径。
- mobile flavor 的入口按钮需自行补一行 `HikerEntry.start(this)`。
