# 前端重写：从「后端数据可视化」到「录口令 → 生成站点 → 点站点播放」

## 一、这次改的是什么

用户指出：之前独立入口里那个 `index.html` 是**项目后端数据可视化 / 开发者自测面板**
（① 入口状态 ② 口令管理表格 ③ 口令数据表格 ④ 生成站点 registry ⑤ 样本规则运行
⑥ 桥接播放记录 ⑦ 兼容性能力表 + 覆盖率 + 日志）。用户明确「不需要这些后端」，
要的是海阔程序真正的前端：

> 输入口令（单口令 / 多口令 / 含密码 / 导入）→ 录入口令后生成站点 →
> 点击站点，则进行站点的播放逻辑。

本次按此重写**应用层前端**，把自测面板整体换成面向终端用户的消费级界面。
口令/站点/规则的真实格式取自用户指定的 `xingchen`
（`com.fongmi.android.tv.api.hk.*` 逆向实现）。

## 三、口令四种录入形态（对齐 xingchen 真实格式）

| 模式 | 处理 |
|---|---|
| **单口令** | 一条口令 → 解析 → 站点 |
| **多口令** | 换行 / 分号分隔；结构化行（JSON/分享/base64/云/URL）整行保留不被分号切碎 |
| **含密码** | 口令带 `(@密码)`、口令后空格跟密码，或输入框单独填密码；云6 走 `(@pwd)` 后缀重试 |
| **导入** | 整段 JSON 配置整体解析；粘贴文本 / 读取剪贴板 / 选择本地文件 |

识别的口令内容格式：
- **云口令** `云1~云10 oooole/{path}` → 逐通道映射真实 URL
  （云1 pastebin / 云2 textdb+外层 base64 / 云5 cmd.im / 云6 pasteme(带 referer+密码) /
  云7 note.ms textarea / 云9 txtpad / 云10 hastebin）；netcut(`/p/`) 与 云3/4/8 明确报错不静默
- **明文分享口令** `￥home_rule￥{json}` / `￥home_rule_v2￥{json}`
- **base64 壳** `base64://@标题@BASE64`（UTF-8 安全解码）
- **裸规则 JSON**（含 `col_type`/`find_rule`，即 rule.json）/ 规则数组
- **配置 URL** → `{sites:[...]}`（TVBox 配置）/ 规则 JSON
- **纯文本行** `名称,http://…`

## 四、点击站点后的播放逻辑链

口令解出的站点带规则（rule.json 原生字段 `find_rule`/`detail_find_rule`/
`searchFind`/`last_chapter_rule`，或站点自带 `rules` 对象）。点站点后：

```
home(分类+推荐) → cate(分类筛选) → search(站内搜索) →
detail(详情+选集) → play(解析播放地址) → HikerHost.play() → App 播放器
```

- 规则在**新鲜作用域**同步执行（`HikerApiSurface.installFresh` 全量 134 API +
  `MY_*` 每页变量），捕获 `setResult` 的**完整值**（不截断，旧 `runInFresh` 只截 200 字符）。
- 结果归一化为 VOD 列表 / 选集，分页、分类、搜索都是真实规则产出。
- 播放走既有同步桥 → 本地 `/action?do=push` → `ServerEvent.push` → App 播放器。

**诚实降级（不假成功）**：`js:` 片段可在 WebView 执行；选择器型规则、Rhino、
Python、私有加密、X5、配置型 `csp_`/`jar` 站点需要 App 原生引擎，
页面给出明确提示而非伪造结果。云口令/配置地址需联网，离线明确提示。
