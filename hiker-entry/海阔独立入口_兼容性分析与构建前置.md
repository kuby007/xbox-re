# 海阔独立入口 · 接口兼容性分析与构建前置结论

> 阶段六 / 2026-11-11
> 承接：阶段一～四验证报告、阶段五《路线决策与落地方案》、阶段六《GitHub 分支交付 · 口令一条龙》
> 本轮命题：**「在首页下部的多功能横按钮加一个入口，不要与首页混用；海阔多变，须先做兼容性分析，最后再落实项目构建 app」**
> 实测：`compat_verify.py` → `compat_report.json` → `hiker_compat_poc.png`（全部离线可复现）

---

## 0. 结论先行

**可以做到，且"不要与首页混用"是唯一正确的做法——不是偏好，是实测的硬约束。**

| 判断 | 结论 | 证据 |
|---|---|---|
| 与首页 WebView 混用 | ❌ **INCOMPATIBLE** | A 组：宿主 `window.fetch` 被双方各覆盖一次、`fongmiBridge` 只有异步 Promise、文档被 `fm-native` 标记 |
| 独立入口 + 同步桥 | ✅ 必须 | B 组 `setResult 3/3`、C 组 `3/3`，页面异常 0 |
| 兼容层是否损失通过率 | ❌ 不损失，反提升 | 全库同口径 23/78 → 31/78（**+8**） |
| 多变形态（Rhino / Python / 加密规则） | ✅ 正确降级 | E 组全部 `degrade-to-engine`，不静默假成功 |

**一句话**：首页那颗按钮只做"跳转"，真正的功能跑在**独立 Activity + 独立 WebView + 独立同步 Java 桥**里；前面写的兼容层 `HikerCompat` 负责把海阔的多变规则收敛到这个独立环境。这也解释了为什么必须"不混用"——混进去会直接把首页 WebHome 的 `fetch` 打坏。

## 2. 海阔"多变"到底多在哪（量化，非感觉）

对 `hiker_54.db` 全库文本（121 条规则 + 8 条 `bigtextdo`，含 115 KB `home_js`）扫描：

| 形态 | 命中 | 对兼容层的含义 |
|---|---:|---|
| `hiker://` 路由 | 3765 | 需独立页面栈，不能靠首页 URL 白名单 |
| `input` / `params` | 2507 | 每页变量注入 |
| `pdfh(` | 1457 | 需 DOM 解析垫片 |
| `$.require` | 1192 | `$` 必须 jQuery 风格化 |
| `lazyRule/clickRule/x5cKey/x5rule` | 962 | `$.fn` 扩展（阶段五实证过缺失即挂） |
| `fetch(` | 884 | **必须是同步字符串** |
| `setResult(` | 573 | 结果回传通道 |
| `MY_URL` | 564 | 每页上下文 |
| `pdfa(` | 509 | 数组解析 |
| `MY_PAGE` | 385 | 分页上下文 |
| `request(` | 369 | **必须是同步字符串** |
| `JavaAdapter/Packages./importPackage` | 63 | **Rhino 专有，WebView 跑不了** |
| `py:` / `chaquo` | 56 | **Python 规则，需 Chaquopy** |
| `evalPrivateJS` / 加密 | 56 | **私有加密规则，需 Java 侧引擎** |
| `fy_bridge_app` | 119 | 原版同步桥痕迹 |

**结论**：这不是一个"写死一种桥"能覆盖的东西。至少存在 **3 类不可在 WebView 执行**的形态（Rhino / Python / 加密规则），必须能识别并显式降级；同时 `fetch`/`request` 的同步语义是 1253 处命中的硬要求。

## 3. 兼容性实证（A / B / C / D1 / D2 / E）

`python3 compat_verify.py`，Playwright + 真实 `fm.html` + 真实规则，**完全离线**。

### A 组：与首页混用 → 判定 INCOMPATIBLE

复刻 `HomeWebController.getSdk():797-920` 的语义（`window.fm.req` 返回 Promise、`fongmiBridge.invoke` 异步回调、`document.fm-native`、debugHook 改写 `fetch`）：

```
宿主 fetch 异步: True   hasHomeSdk: True   documentIsolated: False
shim 覆盖宿主 fetch: True / 宿主反覆盖: True → 全局冲突: True
可用同步桥: []   仅异步: True   判定: INCOMPATIBLE
```

**三条硬冲突**：
1. **全局 `fetch` 争夺**：海阔补齐层要把 `fetch` 改成同步字符串；首页 SDK 要把它变成异步 Promise。同一个 `window` 里后注入者赢，另一方全挂。
2. **桥语义不可调和**：`HomeWebBridge.invoke` 走 `Task.execute` 线程池，结果靠 `fongmiNative.resolve` 回调；海阔规则是 `eval.call(null, fetch(url))` 直接拿字符串。等不到回调。
3. **URL / 作用域污染**：`WebHomeTarget` 限制同源 https + 仅 3 个 `file:///android_asset/webhome/*` 白名单；而海阔要 `hiker://` 任意跳转。且 SDK 会给 `documentElement` 打 `fm-native`、注册 `fmsdk` 事件，彼此污染。

### B 组：独立 WebView + 同步桥（阶段五基线）

`setResult 3/3`，桥 `FM_SHELL.call(req)`，页面异常 0。

### C 组：独立 WebView + 兼容层 `HikerCompat`

```
桥探测: 同步可用=['HikerBridge','FM_SHELL'] 仅异步=False 首页SDK=False 文档隔离=True
setResult 3/3   页面异常 0   warnings=0
```

兼容层正确识别出"独立环境、有同步桥、无首页 SDK"，未产生任何警告。

### D1 / D2 组：全库 78 条，同口径对比（防止虚高）

| 组 | 配置 | setResult | 无异常 |
|---|---|---:|---:|
| D1 | 同步桥 + JsT4 + shim，**无兼容层** | **23/78** | 26/78 |
| D2 | 同上 **+ HikerCompat** | **31/78** | 31/78 |

D1 的 23/78 与阶段五基线**完全一致**，说明口径没漂移；D2 的 +8 来自兼容层每次执行前 `setPage(page)` 补齐 `MY_URL/MY_PAGE` 等每页变量，是可解释的真实增益，不是假阳性。

形态命中（78 条）：`lifecycle 62`、`hiker-scheme 55`、`jquery-style 52`、`sync-fetch 34`、`dom-pdfh 22`、`dom-pdfa 20`、`sync-request 16`、`crypto 3`。

### E 组：多变形态降级 + 反假阳性

| 样本 | runnable | action | 实际 `setResult` | 命中形态 |
|---|---|---|---|---|
| 标准 JS | ✅ | `run-in-webview` | ✅ 影片A | lifecycle |
| Rhino `JavaAdapter` | ❌ | `degrade-to-engine` | — | rhino |
| Python `py:` | ❌ | `degrade-to-engine` | — | python |
| 加密 `evalPrivateJS` | ❌ | `degrade-to-engine` | — | encrypted-rule |
| 同步网络 `fetch+pdfa` | ✅ | `run-in-webview` | ✅ 3 条 | sync-fetch, dom-pdfa, lifecycle |

E 组同样先装配 shim，因此 2 条 `runnable` 样本**真正产出 setResult**（不是只验分类），3 条不支持形态明确报 `unsupported-form` 降级。

`normalize('<html>')` → `sync-string`；`normalize(Promise)` → **`async-promise` / ok=false**。即：异步结果被明确拒绝，不会被 `String(promise)` 静默转成 `[object Promise]` 假成功（阶段二踩过的坑）。

## 4. 兼容性设计决策（据此才动 App）

| 决策 | 内容 | 理由 |
|---|---|---|
| D1 | **入口只是跳转**：首页横按钮 → `HikerActivity.start()` | "不要与首页混用" |
| D2 | **独立 WebView**：不复用 `webOverlay` / `HomeWebController` / `fongmiBridge` | A 组三条硬冲突 |
| D3 | **独立同步 Java 桥** `HikerBridge.req()` 返回 `String` | 首页桥异步，海阔要同步（①②③ 类接口共同要求） |
| D4 | **兼容层四件事**：桥探测 / 语义归一 / 作用域隔离 / 形态降级 | 覆盖第 2 节的多变形态 |
| D5 | **两套横按钮都注册**：`Func`（实际渲染）+ `HomeButton`（设置可显隐排序） | 你说的"多功能横按钮"在不同 flavor 落在不同体系，二者都兼容 |
| D6 | **不动 `homePage` / 不改点播配置** | 上一轮 `koul-onestop` 是 WebHome 首页（混用），本轮按你的要求改独立入口 |
| D7 | **语法 ES5 + Promise** | 仓库 `webhome-devkit` 第 13 章要求 Chromium 50–70 |

### 落到 App 时的兼容性风险清单（逐项已核对源码）

| 改动点 | 风险 | 处理 |
|---|---|---|
| `Func.setDrawable()` 是 if-else 链 | 新 resId 不加分支 → drawable=0，图标空白 | 追加第 7 分支 + 新增 `ic_home_hiker` vector |
| `Func.equals/isSameItem` 按 `resId` 比较 | 新 resId 必须唯一 | 新增独立 `R.string.home_hiker` |
| `HomeButton.ALL = "0,1,2,3,8,4,5,6,7,9"` 硬编码 | 新增 id=10 会改变 `sortedAll()` 长度判断 | 同步更新 `ALL` 与 `getDefaultButtons()`；`insertMissing` 会自动补齐旧用户的偏好串，**向后兼容** |
| `HomeActivity` 有 leanback / mobile 两份 | 只改一份则另一 flavor 无入口 | `Func`/`HomeActivity` 改动落在 leanback；`HikerActivity`/桥/assets 放 `main`，**两个 flavor 共用** |
| `strings.xml` 多语言 | 缺语言会回退英文 | 只加英文基准 + 简体中文，其余按 Android 资源回退 |
| Java 21 / AGP 9.2.1 / compileSdk 37 | 新增代码不能用旧语法 | 用 `switch` 表达式等仓库现有写法，不引入新依赖 |
| `AndroidManifest` | 未注册 Activity 会崩溃 | 在 `main/AndroidManifest.xml` 注册，避免 flavor 差异 |
| 播放出口 | 首页 `fm.play` 是异步 | 独立桥 `play()` 直接调 `VideoActivity.start(SiteApi.PUSH,…)`，与 `HomeWebBridge.playUrl` 同一出口但**不经首页桥** |

## 6. 仍未闭合 / 边界（如实说明）

| 项 | 状态 |
|---|---|
| **完整 APK 编译** | 沙箱 Gradle 9.3.0 / JDK 20 / **无 Android SDK**，仓库要求 Gradle 9.5.1 + JDK 21 + compileSdk 37 + NDK 29 → 无法产出 APK。本轮用 `ecj + android-all.jar` 对新增类做**真编译**作为前置验证 |
| 「多功能横按钮」的精确位置 | 代码里 `Func`（`FuncPresenter` 横排图标+文字，实际渲染）与 `HomeButton`（设置里可显隐排序的 10 按钮）是两套；本轮**两套都注册**，无论你指哪套都有入口 |
| Rhino / Python / 加密规则 | 兼容层只做**识别与降级标记**，真正执行需要 Java 侧 `HkJsRuntime` / Chaquopy / `evalPrivateJS`，仓库未包含这些引擎（阶段五 P2 项） |
| 覆盖率 31/78 | 离线 stub HTML 下的数字，真实站点结构不同，真机需回归 |
| 真机最小探针 | 仍未做（阶段五 P1-1）；本轮是同一 WebView 模型下的离线实证 |
