## 3. 兼容性分析（构建前置逐项）

### 3.1 控件硬上限：4 → 5，刚好不越界
`activity_home.xml` 用的是 `com.google.android.material.bottomnavigation.BottomNavigationView`。
Material 的 `NavigationBarMenu` 常量 `MAX_ITEM_COUNT = 5`，超过即抛异常。原菜单 4 项，新增 1 项
变为 **5 项，等于上限但不超过**。这是本次唯一的结构性硬约束，已单列断言 B02。
（若后续还要再加导航项，必须换 `NavigationRailView` 或改用别处入口，不能继续堆 item。）

### 3.2 与首页 fragment position 映射零耦合（最关键）
手机版首页用 `FragmentStateManager(mBinding.container, ..., position -> switch(position))`，
`case 0..5` 映射 `VodFragment` / `SettingFragment` / `SettingPlayerFragment` /
`SettingEnhanceFragment` / `SettingDanmakuFragment` / `SettingPersonalFragment`，
另有 `selectNavigation()` / `syncNavigationSelection()` 用 `currentPosition` 反查 `R.id.vod` / `R.id.setting`。
**新增导航项一旦占用一个 position，就会整体错位。**

对策：完全照抄现有 `lab` 项的模式 —— 点击后跳独立 Activity 并 `return false`：

```java
if (item.getItemId() == R.id.hiker) { com.fongmi.android.tv.hiker.HikerEntry.start(this); return false; }
```

`return false` 让 `BottomNavigationView` **不把新项设为选中态**，选中项保持原样、
`currentPosition` 不变、`FragmentStateManager` 的 switch 完全不被触发。
验证断言 D01~D05 确认：6 个 case 逐字未改、7 个关键方法体逐字未改、
`R.id.hiker` 只出现在「置可见」与「点击分支」两处、`currentPosition` 赋值语句未新增。

### 3.3 可见性走既有统一通道
`menu_nav.xml` 里 4 个原项全部 `android:visible="false"`，由 `setNavigation()` 统一置可见
（`onResume` / `onConfigEvent(COMMON)` / `onBackInvoked` / `restorePosition` 都会调用它）。
新项沿用 `visible=false`，并在 `setNavigation()` 里补 `findItem(R.id.hiker).setVisible(true)`，
因此**与既有项同生命周期、不引入新的显示路径**，也不受 `LabConfig.getNavEntry()` 开关影响。

### 3.4 跨 flavor 资源与运行时层零改动
- 标题直接用 `main` 的 `@string/home_hiker`（`values` / `values-zh` / `values-zh-rCN` / `values-zh-rTW`
  四套已存在），**不需要改 mobile 的 strings.xml**；`labelVisibilityMode="unlabeled"` 下标题只作无障碍描述。
- `HikerEntry.start(Activity)` 是 `public static`，用**全限定名调用**，因此 `import` 段完全不变、
  不新增任何编译依赖。
- `HikerActivity` 注册在 `main/AndroidManifest.xml`，mobile flavor 自动继承。
- 运行时 8 个 Java 类、assets 容器脚本、leanback 入口均**不在改动清单内**。

### 3.5 CI 源码门禁不受影响
工作流 `Verify mobile search scope feature is present` 的 22 条断言只涉及
`fragment_search.xml`、`dialog_site.xml`、`SearchFragment.java`、`SiteAdapter.java`、
`SiteDialog.java`、`values-zh/strings.xml`，**不含 `menu_nav.xml` 或 mobile `HomeActivity.java`**。
本次改动不会让门禁由绿转红。

### 3.6 发布链路沿用已修复版本
v3 分支上的 `.github/workflows/android-release.yml` 已含上一轮修复：
`Upload workflow artifacts` 带 `continue-on-error: true`、`retention-days: 7`。
非关键临时制品上传失败不再染红 run；Gradle 编译 / v2 签名 / 完整性校验 / Release 创建仍是硬门禁。
